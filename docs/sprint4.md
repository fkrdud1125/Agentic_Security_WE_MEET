# Sprint 4 — 결과 중심 대시보드

기준: `feat/sprint3-commit-watch`의 `918cc5c`. Orca 작업 사본과 분리하여 구현한다.

## 목표와 디자인

설정 패널이 첫 화면을 차지하던 구조를 프로젝트별 보안 상태와 발견 목록 중심으로 바꾼다.
240px 네이비 사이드바, 얇은 구분선, 크게 표시한 위험 등급, 46px 발견 행으로 화면의 밀도를 맞춘다.
계획서의 기본 색상·간격·곡률 토큰과 한국어 심각도 체계를 사용한다. 주요 동작은 프로젝트 추가, 지금 스캔, 보고서다.
모바일 레이아웃은 추가하지 않는다.

## 구현

- 연결된 프로젝트와 결과만 있는 프로젝트를 합치며, 이력·선택 결과·다운로드가 같은 프로젝트를 가리키도록 한다.
- 빠른 프로젝트 전환에서 뒤늦은 API 응답을 무시한다. 다른 프로젝트의 자동 스캔 결과가 현재 선택을 바꾸지 않는다.
- 프로젝트 추가는 모달, 로그인·자동 감시·데이터·테마는 설정 드로어로 옮겼다.
- 빠른 검사와 AI 심층 분석을 스플릿 버튼으로 통합했다. 기존 POST/API와 구독 안내를 유지한다.
- 보안 등급은 열린 발견의 최고 심각도로 산정한다. 오탐 후보와 해결됨은 제외한다.
- 최근 8회 점수 추이, 새 위험·해결 변화, 새 치명·높음 배너를 표시한다.
- 다중 심각도 칩, 상태별 건수 탭, 검색, 필터 초기화로 목록을 탐색한다.
- 상세 드로어는 문제 → 코드 → 수정 방법 → diff → 접힌 판정 정보 순서다.
- 코드와 diff는 textContent만 사용한다. 외부 문자열을 HTML로 해석하지 않는다.
- 드로어는 포커스 트랩·복귀, 배경 inert, Esc, 이전·다음 탐색을 제공한다.
- 시스템·라이트·다크를 지원한다. 저장소 접근 실패에도 동작하며, 외부 theme.js를 CSS 전에 읽어 CSP의 unsafe-inline 없이 테마를 적용한다.
- 토스트 aria-live는 한 곳이다. 수동·자동 스캔 진행, 실패 이유, 알림 권한 거부 안내를 유지한다.
- 폰트·라이선스·theme.js만 asset 화이트리스트에 추가한다. font-src는 self만 허용한다.
- /api/scans 요약에 summary·trigger만 추가했다. 캐시와 나머지 API는 유지한다.

## 확인 방법

```sh
python -m unittest discover -s tests
node tests/test_dashboard_ui.cjs
python tests/dashboard_preview.py --output /tmp/vibescan-demo
vibescan dashboard --results /tmp/vibescan-demo/results
```

Windows에서는 /tmp 대신 저장소 밖의 쓰기 가능한 폴더를 지정한다.
샘플은 실제 사용자 코드를 읽지 않는 합성 데이터다. 결과 없음, 발견 없음, 다수 발견, 8회 추이, AI 실패, 오탐·해결, 미연결 프로젝트를 포함한다.
출력된 preview.html은 화면 검토용이며 실제 스캔·로그인을 실행하지 않는다.

## 검증 상태

- Node UI 회귀: 프로젝트 결합·필터, 등급, 탭, 다중 칩, 검색, 배너, 지연 응답, XSS 텍스트 처리, 복사, 상세 이동, 포커스 복귀, 추이, 알림 중복 방지, 스캔 POST, AI 실패, 보고서, 인증, 저장소 차단, 토큰 hash, 테마 확인.
- Python API: 폰트·테마 허용, 임의·경로 조작 파일 404, CSP, 요약 필드 테스트 추가.
- 현재 로컬 실행 환경에서는 Python TestClient의 Windows socketpair가 제한되어 전체 테스트가 멈춘다. 별도 진단 실행으로 원인을 확인했다. GitHub CI 결과를 최종 확인한다.
- 실제 브라우저 화면 검증과 before/after 스크린샷은 로컬 URL·파일 접근 정책 때문에 아직 완료하지 못했다. 1440×900 / 1280px에서 행 밀도, 드로어 말줄임, 테마 대비의 시각 확인이 남아 있다.
