# Sprint 2 — 로컬 대시보드

v6 계획과 GitHub `main`의 `e187c25`를 대조해 시작했다. Sprint 1은 CLI 로그인·소스 수집·정찰·정적 검사·모델 검토·한국어 보고서까지 구현되어 있다. 실계정 검증과 Semgrep 실행에 대한 기존 한계는 [Sprint 1 기록](sprint1.md)을 따른다.

## 1단계: 저장 결과 조회

- [x] `vibescan` 기본 실행에서 루프백 서버와 브라우저 시작
- [x] 기존 JSON 재사용, 스캔 선택과 결과 새로고침, 별도 출력 폴더 지원
- [x] 위험 점수·열린 발견·심각도 분포·우선 확인 3건
- [x] 미검사/수동 확인 항목과 모델 분석 상태 표시
- [x] 발견 필터·상세 근거·오탐 판정 이유·수정안 복사·보고서 다운로드
- [x] 빈 상태·접근 실패·손상 결과 안내
- [x] Host·Origin 확인과 실행별 접근 키, 외부 자산 없는 CSP, 텍스트로 코드 표시

기존 CLI·결과 형식·SQLite 저장 코드는 유지한다. 조회 API는 결과 JSON을 읽고 `ScanResult`로 변환해 집계를 재계산한다. 임의 경로를 받는 API나 결과 수정 API는 없다. `--results`는 서버를 실행하는 사용자가 선택하는 결과 상위 폴더다.

전체 스캔에서 new/fixed가 모두 0이어도 비교를 수행했다는 뜻이 아니므로 `비교 전`으로 표시한다. 모델의 오탐 후보는 상세 근거와 최초 심각도를 그대로 보존한다. 수정안은 복사만 가능하며 자동 적용하지 않는다.

## 2단계: 로컬 레포 연결과 수동 재스캔

- [x] Git 저장소 루트 경로 연결: HEAD 커밋 확인, 결과·설정 폴더가 저장소 안에 있으면 거절
- [x] 연결 목록을 이력 DB(`connected_repos`)에 저장하고 대시보드에서 선택
- [x] ‘다시 스캔’: 기존 `scan()`으로 HEAD 전체 검사, 기본은 정적 검사이며 ChatGPT 분석은 체크 시에만 사용
- [x] 실행 중 상태 표시·입력 잠금, 동시 실행 요청은 409로 거절
- [x] 완료 시 새 결과 자동 열기, 실패 시 원인 안내와 이전 결과 유지(엔진 예외 내용은 노출하지 않음)

스캔 작업 상태는 대시보드 프로세스 메모리에 둔다. 대시보드를 여러 개 띄워 같은 DB를 쓰는 경우는 지원하지 않는다. 미커밋 변경은 검사하지 않는다.

## 3단계: ChatGPT 로그인과 실패 상태 표시

- [x] 실제 계정으로 ChatGPT 분석 스캔 확인 (사용자 확인, `vibescan-model-test` 샘플 레포)
- [x] 연결 상태 표시: 미등록 / 로그인 필요·만료 / 구독 사용 승인 없음 / 사용 가능. 저장된 세션만 읽고 토큰 갱신·네트워크 호출은 하지 않음
- [x] ‘ChatGPT로 로그인’ 버튼: 기존 `vibescan login` 흐름을 그대로 실행, 동시에 하나만 허용, 5분 제한. 대시보드 탭에서 ChatGPT 승인 화면으로 이동하고, 승인 후 같은 탭의 대시보드로 돌아와 결과를 상태 줄에 표시
- [x] 사용 가능 상태가 아니면 ‘ChatGPT 분석 사용’ 비활성화
- [x] 모델 실패 원인 구분(`SessionError.kind`): 사용량 한도(429) / 구독 자격(403) / 재로그인(401·갱신 거부) / 기타. 스캔은 정적 결과로 완료하고 원인별 안내 표시
- [x] 레포 연결 오류 문구 구분: 폴더 없음 / Git 저장소·커밋 없음 / 하위 폴더 / 결과 폴더가 저장소 안

- [x] 로그아웃: 이 PC에 저장된 ChatGPT 토큰 삭제. ChatGPT 설정의 앱 연결 해제는 사용자가 ChatGPT에서 직접 한다.

PC 등록(`python -m vibescan.register`)은 설치당 한 번이라 CLI 안내로 남긴다. ChatGPT 사용량 페이지 직접 링크는 넣지 않았다.

## 4단계: GitHub 주소로 연결

- [x] `https://github.com/소유자/저장소`(`.git` 허용) 또는 `git@github.com:소유자/저장소.git` 입력 시 설정 폴더의 `github/소유자/저장소`에 `--depth 1` clone 후 연결
- [x] 주소 형식은 github.com 소유자/저장소만 허용. 다른 호스트·경로·`..`은 거절
- [x] 비공개 저장소는 이 PC의 기존 Git 인증(SSH 키·자격 증명 관리자)을 사용. 터미널 입력 대기 없이 실패하고 5분 제한
- [x] 임시 폴더(`github/.partial`)에 복제하고 커밋을 확인한 뒤 옮김. 중단·실패한 복제나 빈 저장소가 이후 연결을 막지 않음. 동시 clone 1개
- [x] 이미 clone한 주소를 다시 입력하면 재연결. ‘다시 스캔’ 전에 원격 기본 브랜치 최신 커밋을 가져와 맞춤(VibeScan 전용 clone이라 로컬 변경 없음)
- [x] 사용자가 고칠 수 있는 엔진 오류(검사 가능한 파일 없음 등)는 원래 문구로 표시, 그 밖의 예외는 일반 문구 유지

Sprint 2의 로그인 → 레포 연결 → 스캔 → 확인 흐름이 완성되었다. 연결 해제·clone 삭제 UI는 없다.

## 검증

- Windows Python 3.13: 전체 단위 테스트 55개 중 54개 통과, 심볼릭 링크 생성 권한이 필요한 1개 건너뜀. `node tests/test_dashboard_ui.cjs` 통과.
- 레포 연결·재스캔: 실제 Git·Semgrep으로 연결 → 스캔 → 새 커밋 후 재스캔, 잘못된 경로 거절, 중복 실행 거절, 실패 후 이전 결과 보존.
- 브라우저(2단계): 임시 데모 레포 연결 → ‘스캔 중…’ 표시 → 완료 후 새 스캔 결과 자동 표시 확인.
- 브라우저(4단계): `octocat/Hello-World` clone 후 ‘검사 가능한 파일 없음’ 안내, `octocat/Spoon-Knife` clone → 스캔 완료 확인. 이후 커밋 반영은 로컬 원격으로 대체한 테스트에서 확인.
- 브라우저(3단계): 미등록 상태 안내·모델 옵션 비활성화·폴더 없음 오류 확인. 로그인 성공·실패 표시와 실패 원인별 안내는 UI 스크립트 테스트로 확인.
- API: 빈 폴더, 기존 결과 호환, 정렬·집계·보고서, 키/Host/Origin 거절, 손상·누락·ID 불일치·크기 제한, 읽기 전용 확인.
- 패키지: 설치 후 저장소 밖에서 HTML·JS·CSS 응답 확인.
- 브라우저: 실제 엔진 결과와 구분한 UI 검증용 표본 사용. 상세·스크립트 문자열의 비실행·수정안 복사·필터·Markdown 다운로드 확인.

JSON 파일을 목록 조회마다 읽는 작은 로컬 이력용 구현이다. 대량 이력에서 느려지면 SQLite에 결과 파일 위치와 조회용 인덱스를 추가한다. 새로운 계정 로그인·실제 LLM 호출과 Semgrep 전체 실행은 이 화면 작업에서 재검증하지 않았다.
